# Watcher procedure (run every tick) — token-frugal

Role: passive reviewer for a repo where several Claude sessions edit branch `dev`
in one working copy at once. **Report only — never edit source, never run git
write commands** (no add/commit/stash/pull/merge/checkout). Only writes allowed
are under `.claude/watcher/`.

Runs every 20 min. Each tick executes in a fresh throwaway subagent (cron job
`3fb9a7cd` in the main session spawns it), so this file IS your context — read it
fully, do the tick, return a terse summary (VERDICT line + up to 3 lines), and
let the subagent exit. Keep it cheap: do the minimum the verdict calls for; do
NOT read the full snapshot, the diff, or run blame on a GREEN tick.

## Every tick

1. `bash .claude/watcher/collect.sh 15`
   It prints a ~20-line **digest** (also at `.claude/watcher/digest.txt`) and
   writes the full `snapshot.txt` to disk. Read only what the digest returns.

2. Branch on `VERDICT`:

   ### GREEN
   - Append ONE line to `.claude/watcher/log.md`:
     `YYYY-MM-DD HH:MM  | GREEN | ahead N/behind M · window:K · <3-word note>`
   - Print one line to chat (noop). **Do not** touch `report.md`. Stop.

   ### NEEDS-REVIEW  (working diff changed since last tick)
   - From the digest's `WINDOW_EDITS` list, pick only files that are *code*
     (skip generated: `schema.d.ts`, `queries.ts`, `types.ts`, `openapi.json`;
     skip tests unless a test is the only change).
   - `git --no-pager diff HEAD -- <those paths>` — review just that. Look for:
     bugs, broken imports, dead code, stray debug/`console.log`, secrets, a change
     that contradicts a sibling file, backend-schema vs frontend-type drift.
   - Cheap checks only if those files changed and it returns fast:
     `python -m ruff check <changed .py>`.
   - If a file in the window appears to be edited by two sessions (same region,
     or a generated file regenerated by more than one), run
     `bash .claude/watcher/blame-sessions.sh <file>` and name the sessions.
   - Rewrite `report.md` (see cap below). Append one `log.md` line.
   - Chat: 2-4 lines.

   ### ESCALATE  (conflict markers, or pull from origin/dev would conflict)
   - Read the relevant `snapshot.txt` sections for the offending files.
   - Run `bash .claude/watcher/blame-sessions.sh <file> ...` for every offending
     file. Name each session: id + task label + last-edit local time.
   - Put the finding + session names at the TOP of `report.md` and the chat.
   - Append one `log.md` line prefixed `ESCALATE`.

## report.md cap
Max ~40 lines. It is a status file, not a history — overwrite it whole. Sections:
Status line, one small table (markers / divergence / diff), "What moved" (bullets),
"Attribution" (only if a hotspot/conflict), "Notes" (<=4 bullets). History lives
in `log.md`, one line per tick.

## If the watcher restarts in a new session
Update `.claude/watcher/self-session-id` with the new id so blame doesn't tag the
watcher's own edits as a culprit.
