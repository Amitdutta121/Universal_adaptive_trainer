Why JSON

Structure is declared by the document, never guessed here. Heading heuristics are not deterministic across books: rules that work on one textbook mis-segment the next, and the result still looks like a valid structure, so the mistake goes unnoticed. Producing the document is therefore outside this application — supply one that already states the book's chapters, sections and section text.

Validation is strict and total: unknown fields are rejected rather than ignored, every section needs non-empty text, and an invalid document is refused in full before anything is stored. Nothing is ever partially imported.

Document shape 
{
  "schema_version": "{{ schema_version }}",
  "title": "Think Python",
  "author": "Allen B. Downey",
  "producer": "my-converter 1.0",
  "page_count": 292,
  "chapters": [
    {
      "number": "1",
      "title": "The Way of the Program",
      "start_page": 17,
      "sections": [
        {
          "number": "1.1",
          "title": "What Is a Program?",
          "start_page": 17,
          "end_page": 18,
          "text": "A program is a sequence of instructions ...",
          "structure_source": "pdf_outline"
        }
      ]
    }
  ]
}

Every chapter needs at least one section, and every section needs non-empty text. title may be null when the source printed no heading — never invent one; the interface then labels the unit by its number or page range. structure_source is one of pdf_outline, markdown_heading, manual, structured_json or producer_inferred — the last marks a boundary you had to guess, which shows as low confidence and makes the book partial. See docs/book_document_example.json for a complete example.
